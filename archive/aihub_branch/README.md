# AI-Hub 「부산시 침수위험 복합 데이터」 갈래 (미채택 보관)

AI-Hub 데이터셋을 검토해 격자·CCTV에 연결했으나 **최종 모델·MCDA 어디에도 반영하지 않았습니다.**
경위는 이슈 [#37](https://github.com/BusanDX2026/BusanDX2026-BigData/issues/37).

## 무엇을 하려 했나

AI-Hub 「부산시 침수위험 복합 데이터」(JPG 114,763 / JSON 114,763, 원본 39.85GB)의
측구(gutter) 촬영 지점을 뽑아 100m 격자·행정동·부산 방범 CCTV에 연결했습니다.
의도는 **"여기가 실제로 이렇게 잠긴다"는 시범구역 사례 앵커**를 확보하는 것이었습니다.

## 미채택 사유 — 관측지점이 15곳뿐이고 공간 편중

라벨링 JSON 전량을 스캔한 결과:

| 단계 | 지점 수 |
|---|--:|
| 원시 gutter 좌표 후보 | 19 |
| (0,0) 결측·부산 bbox 밖 제외 | 17 |
| 80m 이내 중복 병합 | **15** |

**15지점 / 81,224격자 = 0.018%.** citywide 피처가 될 수 없는 밀도입니다.

게다가 공간 분포가 **온천천 회랑(연제구)에 편중**돼 있습니다.

| 행정동 | 지점 |
|---|--:|
| 거제1동 | 3 |
| 연산9동 · 초량3동 | 각 2 |
| 연산8동 · 연산5동 · 문현2동 · 우2동 · 남부민1동 · 중앙동 · 범일5동 · 대연3동 | 각 1 |

연제구만 7/15입니다. 이 상태로 피처를 만들면 **자치구 지문**이 되어,
위약 대조(행정동 난수)에서 기각되는 유형과 같아집니다.

## 사례분석으로도 쓰지 못한 이유

시범구역 케이스스터디 앵커로는 남길 수 있었으나, 붙임 2 분석보고서가 10P 제한이라
온천천 사례 절을 넣지 못했습니다. 결과적으로 **어떤 산출물도 이 갈래를 소비하지 않습니다.**

- `aihub_cctv_매핑.csv` 를 읽는 M·MS·V 스크립트: **0개**
- 붙임 2 활용데이터 13종 목록에 AI-Hub **미포함**

## 보관 파일

- `scripts/S7_AIHub_CCTV_매핑.py` — 라벨링 JSON 스캔 → 격자·CCTV 매핑 (실행 금지)
- `scripts/D2_AIHub_보존패키지.py` — 원본 39.85GB 삭제 전 증빙 추출 (실행 금지)
- `reports/S7_AIHub_CCTV.md` — 실행 리포트 (15지점 최종본)

## 원본 증빙은 그대로 둡니다

D2 가 만든 보존 패키지는 **`공공데이터/raw/15_AIHub_침수위험복합/`** 에 남아 있습니다
(샘플 JSON·이미지, 수치모델 시나리오 매니페스트, 재현빈도별 강우, README).
"이 데이터셋을 검토했고 왜 안 썼는지"의 근거이므로 삭제하지 않았습니다.

## 다시 쓸 수 있는 경우

발표에서 **온천천 실사 이미지**를 시각 앵커로 쓰고 싶을 때. 그때는 피처가 아니라
"모델이 고위험으로 지목한 격자의 실제 모습" 정도의 삽화로만 쓸 수 있습니다.
