# 100m 격자 기반 부산시 호우 전 선제점검 우선순위 분석

**2026년 Big Data 활용 대회 · 빅데이터 분석 및 시각화 부문** · 팀 수문장 · 2026-09-16 제출

부산 전역을 100m 격자 **81,224개**로 나누고, 물리적 침수 감수성을 지도학습으로 평가한 뒤
인구 노출·대응 여건을 결합해 호우 전 **점검 투입 순서**를 제안한다.

> ⚠ **이 산출물은 침수를 예측하거나 경보를 발령하지 않는다.**
> 강우 예보를 입력으로 받지 않는 정적 순위이며, 한정된 자원의 점검 순서를 제안하는 도구다.
> 문서·발표에서 "예측"·"경보"·"시스템"이 아니라 **"제안"·"우선순위"·"점검 순서"** 로 표기한다.
> (`문서/모델링_설계와검증.md` 부록 P2)

## 설계의 핵심 — 왜 인구를 학습에서 뺐나

이 프로젝트의 모든 구조는 한 가지 판단에서 나온다.

타깃은 "침수"가 아니라 **"기록된 침수"** 다. 침수흔적도는 신고와 조사로 만들어지므로
사람이 많은 곳일수록 기록이 남는다. 인구를 설명변수로 넣으면 모델은 물리적 위험이 아니라
**신고 확률**을 학습한다(실제로 PR-AUC가 40~48% 오른다 — 그게 함정이다).

그래서 축을 갈랐다.

| 축 | 방법 | 변수 |
|---|---|---|
| **물리 감수성** | XGBoost 지도학습 | 지형·수문·강우·토지피복·준설 **16개** |
| **인구 노출** | MCDA 가중결합 | 인구·건물·지하공간 |
| **대응 결핍** | MCDA 가중결합 | 배수펌프장 접근성 |

`최종 점수 = 0.50 × 물리 + 0.35 × 노출 + 0.15 × 대응결핍`

인구는 **M5 단계에서 처음 등장한다.** 무엇을 중시할지는 기계가 아니라 행정이 정할 문제이므로
학습이 아닌 가중결합으로 분리했다.

## 핵심 결과

> ⚠ **두 순위를 구분한다.** `hazard_oof`(M9 공간 CV 예측)와 `priority_pct`(M5 MCDA 최종)는
> 다른 순위다. 같은 "상위 10%"라도 수치가 다르므로 항상 기준을 밝힌다.

### ① 물리 침수 감수성 — M9, 자치구 GroupKFold OOF

| 지표 | 값 |
|---|--:|
| PR-AUC (AP) | **0.3059** (양성률 3.56% 대비 8.6배) |
| 상위 10%(81 km²) 침수흔적 포착 / 정밀도 | **59.1% / 21.0%** |
| 상위 10% 위험노출인구 포착 | 67.0% |
| 무작위 점검 대비 적중 효율 | **5.9배** (3.6% → 21.0%) |
| 2020 대형호우 라벨 민감도 | **16.8배** · 상위 10%에서 70.6% 포착 |

### ② 최종 선제점검 우선순위 — M5 MCDA

| 지표 | 값 |
|---|--:|
| 상위 10%(81 km²) 침수흔적 포착 / 정밀도 | 52.0% / 18.5% |
| 상위 10% **위험노출인구 포착** | **90.4%** (279,391명 중) |

노출을 결합하면 침수흔적 포착은 59.1% → 52.0%로 내려가고 인구 포착이 67.0% → **90.4%** 로 오른다.
사람 없는 침수지를 후순위로 내리고 사람 있는 위험지를 올린 것 — MCDA가 의도대로 작동한 결과다.

### ③ 기존 지정구역과의 비교

동일한 **772개** 격자를 선정했을 때(OOF 기준):

| 구분 | 침수이력 정밀도 |
|---|--:|
| 자연재해위험개선지구 중 침수 유형 | 19.3% |
| M9 상위 동일 격자 수 | **55.1%** (**2.85배**) |

침수흔적 격자 2,893개 중 **94.8%(2,744개)가 침수 유형 지정구역 밖**이다.
기존 지정이 잘못됐다는 뜻이 아니라, 그것만으로는 점검 후보가 좁다는 뜻이다.

> ⚠ **비교 기준선은 근사치다.** 재해위험지구 원자료에 경계 폴리곤이 없어
> 지구명을 지오코딩하고 지정면적으로 반경을 역산한 원형 버퍼로 근사했다
> (침수유형 49건 중 45건 지명검색 / 4건 구중심근사).
> 가장 거친 구중심근사 7개 지구를 제외해도 **2.77배**로 결론은 유지된다.

### ④ 변수 기여도 (SHAP)

| 순위 | 변수 | 기여 | 방향 |
|---|---|--:|---|
| 1 | 최저표고 | 23.4% | 낮을수록 위험 ↑ |
| 2 | 하천까지 거리 | 11.3% | — |
| 3 | 맨홀 미준설 비율 | 10.0% | 높을수록 위험 ↑ |
| 4 | 산림 비율 | 9.3% | 많을수록 위험 ↓ |
| 5 | 지형위치지수(TPI) | 7.7% | 주변보다 오목할수록 위험 ↑ |

상위 5개 중 4개가 교과서적인 침수 물리와 일치한다. 3위 **맨홀 미준설 비율**은
관리되지 않은 구역이 실제 침수 기록과 연결된다는 뜻이라 현장 점검 근거로 쓸 수 있다.

## 검증

- **자치구 GroupKFold 5분할 공간 교차검증.** 같은 동네 격자가 학습·검증에 동시에 들어가지
  않도록 자치구 단위로 잘랐다. 무작위 CV는 0.5189, 공간 CV는 0.3059 — **+70% 과대평가**된다.
  성능이 낮은 것이 아니라 정직한 것이다.
- **PR-AUC(AP) 사용.** 양성률 3.56%의 희소 사건에서 ROC-AUC는 과대평가된다.
- **타깃 누수 차단.** 침수흔적·재해위험지구는 설명변수에서 분리했다.
- **위약 대조.** 새 피처 후보는 행정동 난수 대조를 통과해야 채택한다(M8에서 5종 중 4종 기각).
- **라벨 민감도.** 2014년 침수 라벨을 1→0으로 바꾼 홀드아웃 검증.
- **독립 출처 보조 검증.** 119 배수출동 (인구 통제 후 ρ=+0.201, p=0.040).
- **MCDA 가중치 민감도.** ±0.10 변동 시 상위 10% 목록 **90% 유지**, 순위상관 **0.99**.
  동일 가중(1/3씩)까지 흔들면 유지율 63.4%로 떨어진다.

## 코드 읽는 순서 (학습용)

**번호는 실행 순서가 아니다.** M5가 M9 뒤에 온다(작성 순서라서).
전체 의존 그래프는 **부록 D**가 정본.

### 1단계 — 데이터가 어떻게 '격자'가 되나
`S2_좌표통일_부산클립` → `S4_격자_100m_생성` → `S6_마스터_격자_결합`

`grid_id` 가 `"3607_2703"`(행_열) 형식이다. V1에서 래스터 렌더링할 때 다시 쪼개 쓰므로
여기서 규칙을 잡아두면 뒤가 편하다.

### 2단계 — 맞힐 대상이 무엇인가 ★가장 중요
`S5b_홍수위험_침수흔적` — `trace_flag` / `trace_area_ratio` 가 여기서 만들어진다.

> **이 프로젝트의 모든 한계가 여기서 나온다.** 타깃은 "침수"가 아니라 **"기록된 침수"** 다.
> 기장군이 기록의 31%인데 인구는 5%. 이걸 이해해야 뒤의 공간 CV·위약 대조가 왜 필요한지 보인다.

### 3단계 — 피처는 어디서 오나
`S5c_DEM_파생_격자` · **`_hydro.py`** · `S9_토지피복_격자` · `S5a/S5d/S5g`

`_hydro.py` 가 제일 어렵다. `fill_depressions`(priority-flood) → `d8_directions`(**drop>0 강제**)
→ `flow_accumulate` → `hand_from_stream` 순으로 읽는다.
`drop>0` 주석에 D8 결함 경위가 있다 — 이걸 고쳐 성능이 **+25%** 올랐다(부록 R).

### 4단계 — 피처가 어떻게 쌓이나
```
M1 → features.parquet     물리 6
M3 → features_v2          ＋수문 3 (＋튜닝)
M6 → features_v3          ＋토지피복 6
M8 → features_v4          ＋준설미실시 1  = 최종 16피처
```
각 단계가 **추가 → 성능 측정 → 채택 판단**을 반복한다.
M8은 5종 중 4종을 위약 대조로 기각하는 과정이 볼 만하다.

### 5단계 — 학습과 검증 ★핵심
`M9_최종모델_확정` — 시간이 없으면 이것만 읽어도 된다.

- `GroupKFold(n_splits=5)` + `groups=sgg_cd` ← **자치구 단위 분할**
- `scale_pos_weight=27` (= 음성/양성)
- `max_depth=3` · `n_estimators=600` · `lr=0.03` · `min_child_weight=30`
- `tie` 난수 타이브레이크 (동점 처리 버그 수정 흔적)

곁들여 `M2_모델비교` — 랜덤 CV(0.5189) vs 공간 CV(0.3059) 비교가 있다.

### 6단계 — 최종 산출
`M5_MCDA_우선순위_산출` — `0.50×물리 + 0.35×노출 + 0.15×대응결핍`

M9의 `hazard_score.parquet` 을 읽어 인구·건물을 결합한다.
**여기서 처음으로 인구가 등장**한다는 것이 설계의 핵심이다.

강서구만 `hazard_mcda_pct`(물리 지표 동일가중)를 쓰고 나머지는 `hazard_pct`(ML)를 쓴다.
두 갈래를 합친 컬럼이 `hazard_used_pct` — **MCDA 재현 시 이 컬럼을 써야 한다**
(`hazard_pct`로 계산하면 r=0.870까지만 맞는다).

## 작업 규칙

- **API 키·개인정보는 코드에 넣지 않는다.** `secrets/` 또는 환경변수만 (gitignore 확인)
- **추적 경계는 '재현 수단 vs 재현 결과'다.** 수단(스크립트·설계문서·출처 README·실행 리포트)은 넣고
  결과(`output/`, 모든 데이터 파일, 제출본)는 뺀다. **이 저장소는 PUBLIC 이다.**
- 결측은 **0으로 채우지 않는다.** NaN 유지 후 자치구 중앙값 대체
- 새 피처 후보는 **위약 대조(행정동 난수)를 반드시 통과**시킨다.
  SHAP 기여율이 높다고 유용한 피처가 아니다 (M8·M11에서 두 번 확인됨)
- 성능은 **자치구 GroupKFold 수치만** 신뢰한다. 랜덤 CV는 +70% 과대평가
- **백분위 컬럼은 0~1이다.** `rank(pct=True)`를 100배 하지 말 것 (곱하면 노출 축이 100배 지배한다)
