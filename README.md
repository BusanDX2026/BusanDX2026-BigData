# 부산시 호우 시 선제대응 점검 우선순위 권고

**2026년 Big Data 활용 대회 · 데이터분석 부문**

부산 전역을 100m 격자 **81,224개**로 나누고, 물리적 침수 감수성과 인구 노출을 결합해
호우기 이전 **점검 투입 순서**를 권고한다.

> ⚠ **이 산출물은 침수를 예측하거나 경보를 발령하지 않는다.**
> 한정된 자원의 점검 우선순위를 권고하는 도구다. 문서·발표에서 "예측"·"경보"·"시스템"이 아니라
> **"권고"·"우선순위"·"점검 순서"** 로 표기한다. (`문서/모델링_설계와검증.md` 부록 P2)

## 핵심 결과

| 지표 | 값 |
|---|--:|
| M9 침수 감수성 PR-AUC (자치구 GroupKFold5) | **0.3059** (양성률 3.56% 대비 8.6배) |
| 상위 10%(81km²) 침수흔적 포착 / 정밀도 | **59.1% / 21.0%** |
| 상위 10% 위험노출인구 포착 | **90.4%** (279,391명 중) |
| 무작위 점검 대비 효율 | **5.9배** |
| 행정 재해위험지구 대비 (동일 면적 정밀도) | **3.1배** (16.6% → 51.8%) |
| 2020 대형호우 홀드아웃 리프트 | **16.8배** |

부산 침수 기록의 **94.4%가 재해위험지구 밖**에서 발생했다. 이 도구는 규제 대상은 아니지만
침수가 반복되는 **회색지대**를 찾는다.

## 코드 읽는 순서 (학습용)

**번호는 실행 순서가 아니다.** M5가 M9 뒤에 온다(작성 순서라서).
전체 의존 그래프는 **부록 D**가 정본.

### 1단계 — 데이터가 어떻게 '격자'가 되나
`S2_좌표통일_부산클립` → `S4_격자_100m_생성` → `S6_마스터_격자_결합`

`grid_id` 가 `"3607_2703"`(행_열) 형식이다. V1에서 래스터 렌더링할 때 다시 쪼개 쓰므로
여기서 규칙을 잡아두면 뒤가 편하다.

### 2단계 — 맞힐 대상이 무엇인가 ★가장 중요
`S5b_홍수위험_침수흔적` — `trace_flag` / `trace_area_ratio` 가 여기서 만들어진다.

> **이 프로젝트의 모든 한계가 여기서 나온다.** 타깃은 "침수"가 아니라 **"기록된 침수"** 다.
> 기장군이 기록의 31%인데 인구는 5%. 이걸 이해해야 뒤의 공간 CV·위약 대조가 왜 필요한지 보인다.

### 3단계 — 피처는 어디서 오나
`S5c_DEM_파생_격자` · **`_hydro.py`** · `S9_토지피복_격자` · `S5a/S5d/S5g`

`_hydro.py` 가 제일 어렵다. `fill_depressions`(priority-flood) → `d8_directions`(**drop>0 강제**)
→ `flow_accumulate` → `hand_from_stream` 순으로 읽는다.
`drop>0` 주석에 D8 결함 경위가 있다 — 이걸 고쳐 성능이 **+25%** 올랐다(부록 R).

### 4단계 — 피처가 어떻게 쌓이나
```
M1 → features.parquet     물리 6
M3 → features_v2          ＋수문 3 (＋튜닝)
M6 → features_v3          ＋토지피복 6
M8 → features_v4          ＋준설미실시 1  = 최종 16피처
```
각 단계가 **추가 → 성능 측정 → 채택 판단**을 반복한다.
M8은 5종 중 4종을 위약 대조로 기각하는 과정이 볼 만하다.

### 5단계 — 학습과 검증 ★핵심
`M9_최종모델_확정` — 시간이 없으면 이것만 읽어도 된다.

- `GroupKFold(n_splits=5)` + `groups=sgg_cd` ← **자치구 단위 분할**
- `scale_pos_weight=27` (= 음성/양성)
- `tie` 난수 타이브레이크 (동점 처리 버그 수정 흔적)
- 누적 절제를 매 실행 시 직접 계산 (낡은 하드코딩 수치 출력 문제를 고친 것)

곁들여 `M2_모델비교` — 랜덤 CV(0.5189) vs 공간 CV(0.3059) 비교가 있다.

### 6단계 — 최종 산출
`M5_MCDA_우선순위_산출` — `0.50×물리 + 0.35×노출 + 0.15×역량결핍`

M9의 `hazard_score.parquet` 을 읽어 인구·건물을 곱한다.
**여기서 처음으로 인구가 등장**한다는 것이 설계의 핵심이다
(학습에 인구를 넣으면 PR-AUC가 40~48% 오르지만 그건 신고 확률이지 침수 원인이 아니다).

### 곁가지 (본류 이해 후)

| 갈래 | 스크립트 | 성격 |
|---|---|---|
| 강우 축 | `S10 → S11 → MS1 → MS3` | 활성화 강우 등급 — **부가 참고** |
| 독립 검증 | `S12 → MS5` | 119 출동 교차검증 |
| **실패 기록** | `M7` `M10` `M11` `M11b` `M12` | 기각된 시도 — 배울 게 가장 많다 |
| 산출물 | `V1`~`V6` | 그림·표·PDF·제출보조 |

`M12_PU학습` 을 특히 권한다. 누수 차단(중첩 CV)과
"편향된 라벨로만 평가하면 안 되니 보조 지표를 함께 본다"는 평가 설계가 들어 있다.

## 작업 규칙

- **API 키·개인정보는 코드에 넣지 않는다.** `secrets/` 또는 환경변수만 (gitignore 확인)
- **추적 경계는 '재현 수단 vs 재현 결과'다.** 수단(스크립트·설계문서·출처 README)은 넣고
  결과(`06_제출자료/` 표·그림·PDF, `문서/붙임*.md`, 모든 데이터 파일)는 뺀다.
  결과물은 `V1`~`V5` 를 돌리면 재생성된다. **이 저장소는 PUBLIC 이다.**
- 결측은 **0으로 채우지 않는다.** NaN 유지 후 자치구 중앙값 대체
- 새 피처 후보는 **위약 대조(행정동 난수)를 반드시 통과**시킨다.
  SHAP 기여율이 높다고 유용한 피처가 아니다 (M8·M11에서 두 번 확인됨)
- 성능은 **자치구 GroupKFold 수치만** 신뢰한다. 랜덤 CV는 +70% 과대평가
