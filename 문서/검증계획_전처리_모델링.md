# 전처리 · 모델링 검증 계획 (부산 침수 대응 우선순위 분석)

> 원칙: **내가 생각한다 → AI가 구현한다 → 내가 검증한다 → AI와 수정한다 → 내가 최종 확인한다.**
> "돌아간다"에서 끝내지 않고 요구사항 → 정상동작 → 예외 → 데이터 → 성능 → CS → 보안 → 통합 순으로 검증한다.

---

## 0. 이 프로젝트에 맞춘 검증 프레임 치환

일반 웹/백엔드용 항목 일부는 이 프로젝트(배치형 지리공간 + ML 파이프라인)에 안 맞는다. 아래로 치환한다.

| 일반 가이드 항목 | 이 프로젝트에서 대체 |
|---|---|
| 동시성 / Race Condition | 해당 없음(단일 배치). 대신 **재현성**: 같은 입력 → 같은 출력, `random_state` 고정, 중간산출물 행수·해시 기록 |
| DB Index / Transaction / JOIN | **조인 정합성**: 좌표계 일치 여부, 키 매칭률(%), 다대다 폭발(행수 급증), 조인 후 격자 수 불변 |
| HTTP Method / 상태코드 / Timeout | 수집은 종료됨. 대신 **원본 대비 무손실**: 클립·집계 전후 총량(총인구·총면적·레코드수) 보존 검증 |
| 보안(SQL Injection 등) | **인증키·개인정보(생년월일) 하드코딩 금지**, 스크립트에 placeholder, 제출물에서 마스킹, `.env`/키 gitignore |
| API 인증/권한 | 해당 없음 |

**데이터 프로젝트 최우선 항목**(가이드 4번 강화):
- target leakage / 순환참조 (danger_level은 폴더 라벨 → **타깃·피처 어디에도 사용 금지**, 검증 완료된 사실)
- 좌표계(CRS) 일관성 — 전 레이어 **EPSG:5186**
- 전처리 기준 일관성(결측·이상치·정규화 규칙을 S0에서 고정하고 전 단계 동일 적용)
- 공간 자기상관 → 모델 검증 시 **랜덤 K-fold 금지, 구역 홀드아웃**

## 1. 작업 단위 (각 단위 = 검증 1회전)

각 단위는 아래 형식으로 진행한다.

```
[요구사항]  입력 / 정상 출력 / 실패 시 동작
[구현방향]  내가 먼저 생각 (어떤 라이브러리·방식·자료구조)
[AI 요청]   이 단위만, 범위 좁게. "수정 말고 구현. assert + 요약통계 출력 포함"
[검증]      아래 체크리스트 중 해당 항목
[결과]      통과 / 문제(문제·근거·재현) → 최소수정 → 재검증
```

## 2. 전처리 단계 (S)

### S0. 작업 규약 고정 (결정 단계 — 내가 정한다)

| 항목 | 결정할 것 |
|---|---|
| 좌표계 | EPSG:5186 (Korea 2000 Central Belt) — 확정 |
| 분석 격자 | 100m fishnet, 원점·정렬 기준(SGIS 격자와 정합? 독자 원점?) |
| 부산 경계 | `01_행정경계/2.경계/행정동` dissolve → 단일 폴리곤. 해안선·도서(가덕도 등) 포함 여부 |
| 결측 규칙 | 지표별: 0 대체 / 제외 / 인접보간 중 무엇을 언제 |
| 이상치 규칙 | 좌표 부산 밖(강우관측 19%), 침수심 음수·과대값 처리 방식 |
| 정규화 | min-max / robust(분위) / 로그변환 대상 |
| 산출물 규칙 | `가공데이터/` 폴더 구조, 파일명, 격자ID 컬럼명(`grid_id`), CRS 명시 |

→ **검증**: 규약 문서화. 이후 모든 단계가 이 규약을 어기지 않는지 매 단계 확인.

### S1. 압축해제 · 무결성

- 입력: `raw/04_.../*.zip` (17개), 정상: shp 컴포넌트 4~5종 세트 완비 / 실패: 손상 zip 목록
- 검증: ④ 데이터 — zip별 압축 파일 수, shp feature 수, .prj 존재, 깨진 파일 0

### S2. 좌표계 통일 (→ EPSG:5186)

- 입력: SGIS 5179 / DEM 30m 4326 / 침수흔적도 3857 / 홍수위험지도·건물·5m DEM 5186
- 정상: 전 레이어 5186, 재투영 후 부산 영역 좌표범위 정상 / 실패: prj 없음·불명 CRS
- 검증:
  - ④ 데이터: 재투영 전후 **면적·둘레 변화율**(작아야 함, 5179↔5186은 극소), bounding box가 부산 범위(약 X:380k–420k, Y:150k–200k 근처)
  - ⑦ CS: 왜 5186인가 설명 가능(홍수위험지도·건물이 이미 5186, 손실 최소)
  - ⑧ 통합: 재투영 결과를 QGIS에서 위성영상과 눈으로 정합 확인(1~2개 레이어)

### S3. 부산 클립

- 입력: 전국 데이터(SGIS 통계·경계, 배수펌프장, 침수흔적도 전국)
- 정상: 부산(시도코드 26) 영역만 / 실패: 경계 걸친 폴리곤 처리(교집합 vs 포함)
- 검증:
  - ④ 데이터: 클립 전후 레코드 수, **부산 시군구 16개 전부 존재**, 클립 면적 합 ≈ 부산 면적(약 770 km²)
  - ⑤ 성능: 전국 격자·건물 클립 시 공간인덱스(STRtree) 사용, 브루트포스 금지

### S4. 분석 격자 생성

- 입력: 부산 경계, 정상: 100m fishnet ∩ 부산 경계, 각 셀 `grid_id` / 실패: 원점 어긋남
- 검증:
  - ④ 데이터: 격자 수(약 7만~9만), 셀 면적 정확히 10,000㎡(경계셀 제외), 중복 `grid_id` 0
  - ⑦ CS: 격자를 List가 아니라 GeoDataFrame + 공간인덱스로. 조인은 `sjoin`
  - ③ 경계값: 부산 최북단/최남단(가덕도)/도서 셀 포함 여부 규약대로

### S5. 레이어별 격자 집계

각 하위 단위마다 **"총량 보존"** 을 반드시 확인한다.

| 지표 | 집계 방법 | 핵심 검증 (④ 데이터) |
|---|---|---|
| 인구(1km→100m) | 면적가중 배분 (또는 건물 dasymetric) | 배분 후 **부산 총인구 = 원본 총인구**(±0.1%), 음수·NaN 0 |
| 건물 | 격자별 ∑연면적, ∑(지하층수>0 연면적), 용도별 | 격자 합계 = 부산 건물 총수(472,608)·총연면적. 한 건물이 여러 격자에 걸칠 때 중복/누락 |
| 홍수위험지도 | 격자별 침수심 max·mean, 침수면적 비율 | 침수심 범위(0~수 m), 폴리곤 없는 셀 = 0 vs NaN 규약대로 |
| 침수흔적도(검증 타깃) | 격자별 침수흔적 유무(0/1), 횟수, max 침수심 | 부산 479폴리곤이 격자에 온전히 매핑, 3857→5186 재투영 후 위치 정상 |
| DEM 30m | 격자별 mean·min 표고, 저지대 비율(임계값), 경사, 흐름누적/TWI | **해수면 근처 음수 표고**, no-data 처리, 산악부(산복도로) 값 타당성 |
| DEM 5m | (시범구역) 위와 동일, 도엽 mosaic | 도엽 경계 이음새 불연속 없음 |
| 배수펌프장 | 격자→최근접 펌프장 거리, 서비스권역(버퍼) 내/외 | 부산 80개소 좌표(위경도→5186) 육상에 위치, 거리 계산 단위(m) |
| 강우(ASOS) | 연최대 일강수량·1시간최다강수량 → 재현빈도(Gumbel 등) → 격자 부여 | 지점 2개(부산159·북부산296)뿐 → **단일값 전역 적용인지 보간인지 명시**, 재현빈도 곡선 적합도 |

- ⑤ 성능: 47만 건물 × 격자 sjoin, 침수흔적 폴리곤 오버레이 — 벡터화·공간인덱스 필수. `.iterrows()` 루프 금지
- ⑦ CS: 최근접 탐색은 KDTree/STRtree(O(log N)), 전수비교(O(N·M)) 금지

### S6. 마스터 격자 테이블 결합

- 입력: S5 산출 지표들, 정상: `grid_id` 기준 outer/left join → 격자당 1행 / 실패: 조인키 타입 불일치
- 검증:
  - ④ 데이터: 조인 후 **행 수 = S4 격자 수**(불변), `grid_id` 중복 0, 지표별 결측률·결측 패턴(특정 지역 몰림?)
  - ⑦ CS(조인 정합성): 다대다 조인으로 행 폭발 안 났는지, 키 매칭률 100%

### S7. AI-Hub CCTV 30지점 매핑

- 입력: AI-Hub 폴더명 30개(`{ID}_{구}_{지점명}`), `09_CCTV` csv
- 정상: 30지점 전부 위경도 부여 + `grid_id` / 실패: 매칭 실패 지점은 지오코딩 폴백
- 검증:
  - ④ 데이터: 30/30 매칭, 좌표가 해당 자치구 안, 온천천 수계 지점이 시범구역 격자에

### S8. 최종 품질 리포트

- 검증(⑧ 통합·⑨ 장애 대비): 마스터 테이블 결측/이상치/분포/상관/스케일 요약, 지표 간 상관행렬(다중공선성 경보), 시각화 1장으로 육안 sanity

## 3. 모델링 단계 (M)

### M0. 모델링 요구사항 재확인 (내가 정의)

- 산출물: 격자/행정동 **우선순위 지수 지도** + 시범구역 사례분석
- 타깃 후보: 침수흔적 발생여부(0/1) / 침수면적·심 / 재해위험지구 지정 / 재해연보 시군구 피해
- **금지: danger_level (폴더 라벨), AI-Hub를 지도학습 타깃으로**
- 검증(①): 이 지수가 "무엇을 예측/평가"하는지, 정상·실패 정의를 한 문장으로

### M1. 지표 정규화 · 방향 정렬

- 검증 ④: 정규화 후 [0,1] 또는 z, **위험↑ → 점수↑ 방향 통일**(표고는 낮을수록 위험 → 부호 반전), 이상치가 정규화 스케일 왜곡 안 하는지(robust 사용 검토)

### M2. 가중치 산정 (2방식 병행)

- (a) AHP(쌍대비교) 또는 엔트로피 가중
- (b) 지도학습(RandomForest/XGBoost, 타깃=침수흔적) + **SHAP** 중요도
- 검증:
  - ④ 데이터 누수: 피처(홍수위험지도)에 타깃(침수흔적)이 이미 녹아있는지 — 홍수위험지도는 시뮬레이션 산출이라 침수흔적과 독립인지 명시. 아니면 순환
  - ⑤ 성능: 격자 ~8만 × 피처 수십 개 — 학습 가능 규모
  - ⑥ CS: 왜 트리모델인가(비선형·상호작용·해석), 대안(로지스틱)과 비교
  - 결과 비교: (a)와 (b) 가중치가 크게 다르면 원인 분석

### M3. 지수 계산

- 검증 ④: 가중합 결과 분포, 상·하위 격자 육안 확인(상위=실제 저지대·상습침수 맞는지)

### M4. 모델 검증 (가장 중요)

- 침수흔적도 대비: **AUC, 순위상관(Spearman)**, 상위 N% 격자의 침수흔적 포착률
- 재해연보 시군구 피해액 대비 순위상관
- **공간 교차검증**: 자치구/블록 홀드아웃(랜덤 K-fold 금지 — 공간 자기상관)
- 검증:
  - ③ 예외: 침수흔적 없는 자치구(중구 3건)에서 지표가 과소평가되는지
  - ⑦ CS: 왜 공간 CV인가 설명 가능
  - ④ 다중공선성: DEM저지대 ↔ 홍수위험지도 상관 높음 → 회귀계수 해석 주의, VIF 확인

### M5. 공간통계

- Moran's I(전역 공간자기상관), LISA/Getis-Ord(핫스팟 클러스터)
- 검증 ④: 가중치 행렬(인접/거리) 정의 명시, 유의수준(순열검정) 표기

### M6. 민감도 분석

- 가중치 ±20%, 정규화 방식 교체, 격자 100m→250m 바꿔도 **상위 우선순위 순위가 안정적인가**
- 검증 ③⑤: 파라미터 스윕이 결과를 뒤집으면 그 지표에 결론이 취약 → 보고서에 명시

### M7. 시범구역 사례분석

- AI-Hub `water_area/water_side` 세그멘테이션 → 프레임별 수면 픽셀 비율(px, 해상도 정규화) vs ASOS 강우 vs 낙동강통제소 수위
- 검증 ④: area가 px²임(m² 아님) 재확인, 해상도 5종 정규화, 파일명 시간창 2.8% 불일치 제외

### M8. 재현성 · 산출물 정리

- 검증 ⑧: 스크립트 처음부터 재실행 → 동일 결과. `scripts/` + `README` + 이 문서 = 제출 재현성 자료. 인증키·생년월일 placeholder 확인
