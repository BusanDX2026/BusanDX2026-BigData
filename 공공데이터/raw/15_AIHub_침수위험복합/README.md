## 데이터셋 구성 — 두 종류가 섞여 있다

### ① 침수위험 지역 라벨링 데이터  ← **본 분석에 사용함**

CCTV·측구 실사 이미지에 침수 라벨. `INFO.gutter_position_lat/lon` 으로 관측지점 좌표 제공.

- **사용처**: `scripts/전처리/S7_AIHub_CCTV_매핑.py`
- **추출 결과**: 측구 관측지점 **19개** → `aihub_관측지점_원시.csv`
- **연계 결과**: 부산 방범 CCTV 최근접 매핑 → `aihub_cctv_매핑.csv`
- 용도는 시범구역 사례분석·검증. **모델 피처로는 쓰지 않음.**
- S7 은 캐시(`aihub_관측지점_원시.csv`)가 있으면 원본을 스캔하지 않으므로 **원본 없이도 재실행 가능**.

### ② 침수위험 수치모델 이미지 데이터  ← **사용하지 않음**

부산시 안전도시포털(safecity.busan.go.kr) 기반 침수 시뮬레이션 결과를
항공사진 타일 위에 폴리곤으로 오버레이한 것.

| 구분 | 지역 | 이미지 |
|---|---|--:|
| 내수 | 동래구·북구·사상구·중구 | 15,742 |
| 외수 | 동천·수영강·온천천 | 9,021 |

**재현빈도 8종(030/050/080/100/150/200/300/500yr) × 지속시간 3종(60/120/180분) = 23개 시나리오**,
각 JSON 에 `1HR_RAINFALL`·`24HR_RAINFALL` 명시. 폴리곤은 **침수심 9등급**(ANNOTATIONS.ID 1~9).

→ 상세: `수치모델_시나리오_매니페스트.csv`, `수치모델_재현빈도별_강우.csv`

## ②를 쓰지 않은 이유 (2026-09-04 판단)

이 데이터는 우리가 이슈 #26·#29 와 설계문서 부록 E 에 **"해소 조건"으로 적어둔 바로 그것**이다
(수리모델로 격자별 임계강우 산출 / 사건 수 확대). 그럼에도 채택하지 않았다.

**결정적 장애 — 지리참조 정보가 데이터에 전혀 없다.**

- 폴리곤 `COORDINATE` 는 **이미지 픽셀 좌표**(2400×1600 기준). 위경도가 아니다.
- `INFO` 에 좌표·bbox·타일 인덱스 필드 없음. JPG 에 EXIF·GeoTIFF 태그 없음.
- 따라서 격자에 얹으려면 **항공사진 타일을 기저지도에 영상정합**해야 한다.

**부수 제약**

- 커버리지가 부분적: 내수 4개 자치구 / 16개. 우리 모델은 전역을 다룬다.
- 타일 번호에 결번 존재(동래구 030yr_060 은 1~331 중 259개) — 침수 발생 타일만 수록.
  단, **타일 번호는 시나리오 간 일관**해서(같은 00001 = 같은 위치) 한 번 정합하면 전 시나리오 적용 가능.
- 더 싼 경로가 있다: `INFO.URL = safecity.busan.go.kr`. 원본 침수예상도를 부산시에 GIS 로
  요청하는 편이 영상정합보다 확실하다. 이미 본선 진출 시 요청 목록에 있음(하수관망과 함께).

**JSON 만 남기는 선택지는 성립하지 않는다.** 폴리곤이 픽셀 좌표라 원본 이미지가 없으면
지리참조 자체가 불가능하다. 즉 이 데이터는 **전부 남기거나 전부 버리거나**다.

## 나중에 ②를 되살리려면

1. AI-Hub 에서 재다운로드 (dataSetSn=71793)
2. 지역·시나리오별 타일 2~3장을 브이월드 항공영상에 수동 정합 → 타일 격자 원점·크기 추정
3. 타일 번호 → 지리좌표 변환식 검증 후 전 타일 일괄 변환
4. 픽셀 폴리곤 → EPSG:5186 → 100m 격자 래스터화
5. 재현빈도별 침수예상 범위를 MS3 등급 임계 보정에 사용

또는 **부산시 안전도시포털/하수도과에 원본 GIS 를 직접 요청** (권장).
